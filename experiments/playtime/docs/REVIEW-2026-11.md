# Bird's-eye review, November 2026

status: idea

A look over the whole repo on 2026-11-09 for blind spots, structure and cheap chances. What came
of it so far: the spike ownership table and the reusable code (ENGINE-MERGE.md, EM5/EM6), the DNA
round-trip spec and the breeds in src (MIPO-BREEDS.md). The rest, cheap now and dearer later:

- **Saves for the player.** Nothing writes to LÖVE's save folder but the flight recorder: on the
  phone a child's Mipo or room is gone on restart. WORLDS-AND-DOORS W2 and DOLL-PLAY F4 wait on
  it. Even a one-page design of where player saves live helps, before breeds and families add to
  what a save holds.
- **A scene format version that moves.** `src/scene-save.lua` writes `version = "1.0"` always;
  migrations are spread over `texture-names`, `migrateDNA` and the backfills in `io.lua`. One
  version number and one ordered list of migrations, before there are saves out in the world.
- **Build outputs in git.** `webtest/output*/game.data` (~18 MB each) are tracked and get committed
  again with each web build: one `.gitignore` line. The monorepo's `.git` is 661 MB; the biggest
  blobs are a 42 MB wav, `.kra`/`.xcf` art and a zip (history cleanup not urgent).
- **Errors that vanish.** 65 `pcall`s in src; several in `shapes.lua` drop the error, so a shape
  that fails to build fails silently.
- **Tests worth having:** small pure modules without a spec: `polygon-ops`, `spline`,
  `mesh-weights`, `scene-save`.
- **Focus.** 15 active plans; the commits went to light, materials, bark and tracks while the
  breeds focus sat at its late steps. Not a code problem, written down so it's seen.

Corrected on the day: Mipo saving was not untested (`character-persistence_spec.lua`), and the
seeded Mipo snapshot already existed (`claudetools/snapshot.sh ... mipos`).
